Silero VAD 도입 설계

recordUp · STT 단계 · 작성 2026-10-19 · 실행 지시문 docs/specs/silero-vad-goal.md

요약
지금 앱도 VAD를 쓰지만, 음량 기반 EnergyVAD로 30초 분할 지점만 고른다. 무음 구간도 모두 Whisper가 디코딩하므로 환각 문장이 생긴다.
Silero VAD(신경망, MIT)를 CoreML로 동봉하고 WhisperKit의 VoiceActivityDetector 확장점에 끼운다. 그리고 음성 구간만 clipTimestamps로 넘겨 무음을 건너뛴다.
WhisperKit 내부 수정이나 새 Swift 패키지 없이, 새 파일 1개와 기존 파일 몇 곳 수정으로 끝나는 것이 기본안이다.

1. 현재 동작 (코드로 확인)

항목현재근거

VAD 종류EnergyVAD, 프레임 0.1초, 임계값 0.02 고정. 설정에서 지정하지 않으면 이것이 쓰인다WhisperKit EnergyVAD.swift, WhisperKit.swift의 voiceActivityDetector ?? EnergyVAD()

따라서 회의 전후의 정적, 긴 침묵, 소음만 있는 구간이 그대로 디코딩된다. "시청해 주셔서 감사합니다" 같은 환각 문장은 이런 구간에서 나온다. 에너지 임계값이 고정이라 작은 목소리는 무음으로, 에어컨 소음은 음성으로 잘못 판정될 수도 있다.

2. 목표와 범위

  • 목표 1: 무음·소음 구간을 Whisper에 넣지 않아 환각 문장을 없앤다.
  • 목표 2: 30초 분할 지점을 신경망 판정으로 골라 문장 중간이 잘리는 일을 줄인다.
  • 목표 3: 무음이 긴 녹음의 전사 시간을 줄인다.
  • 범위 밖: 실시간 녹음, 화자 분리 모델 교체, Windows 판.

3. 결정과 대안

D1. 모델을 어떻게 가져오나

안내용장점단점
A. CoreML 변환본 + 자체 래퍼 (추천)HF FluidInference/silero-vad-coreml 모델 파일만 받아 동봉하고, 100줄 안팎의 Swift 래퍼로 호출한다새 Swift 의존성 없음. WhisperKit과 같은 CoreML 경로. 크기 수 MB 이하로 예상입출력 텐서 형식을 직접 맞춰야 함. 변환본 품질은 M0에서 확인해야 함
B. FluidAudio 패키지Apache 2.0 SDK의 VadManager.segmentSpeech를 쓴다후처리·분할 로직이 이미 있음ASR·화자 분리까지 든 큰 패키지라 WhisperKit과 역할이 겹침. 기본이 런타임 HF 다운로드라 오프라인 설정 필요. Swift 6 이상 요구
C. 직접 변환snakers4/silero-vad 원본을 coremltools로 변환버전을 직접 고름. 출처가 가장 분명변환·검증 작업이 큼. A가 막힐 때의 대안

A를 기본으로 하되, M0에서 변환본의 라이선스와 정확도가 확인되지 않으면 C로 간다. B는 래퍼가 예상보다 커질 때만 재검토한다.

D2. 앱에 어떻게 끼우나

안내용판단
VoiceActivityDetector 상속 + clipTimestamps (추천)SileroVAD가 voiceActivity(in:) -> [Bool]을 구현해 WhisperKitConfig(voiceActivityDetector:)로 주입한다. 음성 구간은 공개 함수 calculateActiveChunks로 구해 clipTimestamps로 넘긴다WhisperKit 공개 확장점만 쓴다. 분할 지점과 건너뛰기를 한 모델로 해결
오디오를 잘라 여러 번 전사음성 구간마다 transcribe를 따로 부르고 시각을 보정시각 보정·문맥 단절을 직접 처리해야 함. 불필요
전사 후 필터전사 결과에서 VAD 무음 구간 문장을 지움시간 절감이 없음. 건너뛰기가 실패할 때의 보완책으로만 고려

D3. 확률을 구간으로 바꾸는 후처리

Silero 원본 get_speech_timestamps 기본값을 출발점으로 하되, 회의 녹음에 맞게 무음과 여백을 늘린다. 최종 값은 M4 측정으로 정한다.

D4. 사용자 설정

설정 화면에 "무음 구간 건너뛰기" 토글 하나만 둔다(vadSkipSilence, 기본 켬). 끄면 Silero는 분할 지점 선택에만 쓰인다. 작은 목소리가 잘리는 녹음을 만났을 때 사용자가 바로 되돌릴 수 있게 하는 안전장치다. 임계값 같은 세부 값은 노출하지 않는다.

5. 미확인 항목

이 문서를 쓴 환경에서는 프록시가 Hugging Face를 막아 아래를 확인하지 못했다. M0에서 확인한다.
  • FluidInference/silero-vad-coreml의 라이선스 원문, Silero 버전, 파일 이름·크기, 입출력 텐서 이름과 형태
  • 변환본이 512샘플 단위인지, 여러 프레임을 한 번에 받는 형태인지 (FluidAudio 문서는 256ms 단위 확률을 언급)
  • CoreML 호출을 프레임마다 할 때의 속도 (1시간 오디오 ≈ 112,500 프레임)
  • clipTimestamps를 줄 때 결과 세그먼트 시각이 원본 기준 절대 시각인지
참고: FluidAudio (Apache 2.0, 모델은 MIT/Apache 2.0이라고 명시), 2차 출처 DictionLabs/silero-vad-coreml 카드는 FluidInference 변환본을 MIT로 재게시했다고 적는다.

6. 실행 계획

M0
사전 검증 앱 코드 변경 없음
  • 모델 확보와 입출력 확인. 원본 Silero와 프레임별 확률 차이 0.05 이하
  • 1시간 오디오 VAD 처리 30초 이하
  • 테스트 세트 T1~T4를 만들고 현재 앱으로 기준선 측정
승인 지점 1 — 모델 출처·통합 방식·기준선을 보고하고 멈춘다.
M1
SileroVAD 구현
  • VoiceActivityDetector 상속, 후처리, 폴백, selfCheck
  • 완료 기준: 빌드 통과, assert 통과, 모델이 없어도 EnergyVAD로 전사됨
M2
무음 건너뛰기
  • clipTimestamps 연결, 음성 없음 처리
  • 완료 기준: 화자 분리 정렬 정상, 세그먼트 시각이 원본과 일치
M3
번들·설정·문서
  • fetch-models, AppPaths, 설정 토글, 고지·문서
  • 완료 기준: ./Scripts/release.sh pkg에 모델 포함, 크기 증가 5MB 이하
M4
검증과 조정
  • T1~T4 재측정, 기준선과 비교표
  • 통과 기준: T2·T3 환각 0건, T1·T4 누락 증가 없음, T2·T3 전사 시간 감소
승인 지점 2 — 결과를 보고하고 멈춘다. 커밋은 지시가 있을 때만.
