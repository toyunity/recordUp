DESIGN + 단계별 실행 계획

로컬 AI 도구 연결 관리.

설정에서 claude · codex · gemini 등 로컬 AI CLI의 연결 정보(경로 · 버전 · 로그인 상태)를 관리하고, 회의록 생성에 쓸 기본 엔진을 고른다. 현재 claude -p에 하드코딩된 생성 백엔드를 선언적 도구 레지스트리로 일반화한다.

핵심 5결정

  1. 선언적 레지스트리. 각 도구를 번들 ai-tools.json의 데이터(스펙)로 정의 → 도구 추가가 대부분 데이터 변경. 기존 prompts/·release-notes.json 패턴과 동일.
  2. Locator/Runner 일반화. ClaudeBinaryLocator·ClaudeRunner를 도구 id로 파라미터화한 AIToolLocator·AIToolRunner로 대체.
  3. 전역 기본 엔진. 설정에서 기본 엔진 1개(defaultEngineID) 선택 → 모든 회의록 생성에 적용. per-run 오버라이드 없음.
  4. 연결 상태 = 탐지 + 버전 + 로그인. 인증은 자격증명 파일 존재 휴리스틱(없으면 "확인 불가"). round-trip 생성은 하지 않음.
  5. 무중단 마이그레이션. 구 claudeBinaryPath → aiToolPath.claude 이전, 기본값 claude → 기존 사용자 동작 불변.

    "versionArgs": ["--version"],
    "invocation": { "args": ["-p"], "promptVia": "argTail" },
    "auth": { "type": "credentialFile", "paths": ["~/.gemini/oauth_creds.json"] } }
]
  • promptVia: stdin(claude, 기존 동작) | argTail(프롬프트를 마지막 인자로 추가 — codex exec "<prompt>", gemini -p "<prompt>"). 두 모드로 세 도구 모두 커버.
  • auth.type: credentialFile(경로 중 하나 존재 → 로그인 추정) | command(실행 후 successPattern 매칭) | 없음 → "확인 불가".
  • 탐지 = candidatePaths + /bin/zsh -lc 'command -v <id>' login-shell 폴백 (기존 discoverViaLoginShell 일반화).
⚠ 구현 단계 검증 (데이터라 한 줄 교정)

codex 비대화형 호출(codex exec "…" 가정) · gemini 비대화형 호출(gemini -p "…" 가정) · codex/gemini 자격증명 파일 경로는 실제 설치본 기준으로 확인한다. stdin 방식이 맞으면 promptVia: "stdin"으로 변경.

STATE

상태 모델

struct AIToolStatus {
    let toolID: String
    var detected: Bool
    var path: String?
    var version: String?     // "v1.0.0"
    var auth: AuthState
}
enum AuthState { case loggedIn, loggedOut, unknown, checking }

프로브는 백그라운드 Task(Process 호출)에서 수행하고 결과는 @MainActor에서 갱신. UI는 절대 throw를 받지 않으며, 실패는 detected=false / auth=.unknown으로 흡수한다.

AI 도구 연결
회의록 생성에 사용할 로컬 AI CLI를 관리합니다.

기본 생성 엔진:   ( • Claude )  ( ○ Codex )  ( ○ Gemini )
┌────────────────────────────────────────────────┐
│ ✨ Claude Code     v1.0.0    ● 연결됨  ● 로그인     │
│ /opt/homebrew/bin/claude                          │
│ [자동 탐지] [경로 지정…] [테스트]          [✓ 기본] │
└────────────────────────────────────────────────┘
┌────────────────────────────────────────────────┐
│ ◆ Codex            —         ○ 미설치              │
│ 경로를 찾을 수 없습니다                             │
│ [자동 탐지] [경로 지정…] [테스트]        [기본 설정] │
└────────────────────────────────────────────────┘
  • 경로 지정… = NSOpenPanel(실행파일 선택, isExecutableFile 검증 후 저장)
  • 자동 탐지 = 해당 도구 재탐지(캐시 무시) · 테스트 = 탐지+버전+인증 재프로브(생성 호출 없음)
  • 기본 엔진은 연결된 도구만 선택 가능. 미탐지 도구 라디오는 비활성

INTEGRATION

생성 연동 · 마이그레이션

  • TranscribeJob Phase 2 → AIToolRunner.generateMinutes(tool: registry.defaultTool(), …)
  • 기본 엔진 미탐지 시 조기 실패: "기본 엔진 〈name〉을(를) 찾을 수 없습니다. 설정 › AI 도구에서 경로를 지정하세요."
  • 마이그레이션: 첫 실행 시 구 claudeBinaryPath가 있고 aiToolPath.claude가 없으면 값 이전. defaultEngineID 기본값 "claude"
  • 에러 타입: ClaudeRunnerError → AIToolRunnerError (binaryNotFound(toolName) · nonZeroExit(toolName, code, stderr) · noOutput)

EXECUTION PLAN

단계별 실행 계획 — 5 Phase

각 Phase는 건드리는 파일 · 체크리스트 · 완료 게이트로 구성한다. Phase 순서대로 빌드가 항상 통과하도록 의존 역순이 아닌 "아래에서 위로"(데이터→모델→런너→UI) 진행.

Phase 1 · 도구 레지스트리 데이터·모델

의존 없음

신규: AITool.swift · AIToolRegistry.swift · Resources/ai-tools.json  |  수정: project.yml(리소스 번들 확인)

  • AITool.swift — Codable struct + InvocationSpec{args, promptVia} + AuthSpec{type, paths/command, successPattern} + invocationArguments(prompt:) 순수 함수
  • ai-tools.json — claude/codex/gemini 3종 (위 스키마)
  • AIToolRegistry — 번들에서 디코드, tool(id:), defaultTool()(UserDefaults defaultEngineID, 기본 "claude")
  • project.yml — Resources/ 글롭에 ai-tools.json 동봉되는지 확인
GATE: ./Scripts/build.sh 통과 + 레지스트리가 3개 도구를 디코드(임시 로그로 확인 후 제거)

Phase 2 · 탐지 · 상태 (Locator)

Phase 1 의존

신규: AIToolLocator.swift

  • 경로 탐지 — candidatePaths(~ 확장) + login-shell 폴백, 결과 aiToolPath.<id> 캐시
  • version(of:) — versionArgs 실행 후 첫 토큰 파싱("v…")
  • authState(of:) — credentialFile 경로 존재 검사 → loggedIn/loggedOut, 스펙 없으면 unknown
  • 마이그레이션 — 구 claudeBinaryPath → aiToolPath.claude 1회 이전
GATE: 빌드 통과 + claude 경로·버전이 기존과 동일하게 탐지됨(수동)

Phase 3 · 생성 Runner 일반화 + 호출부 교체

Phase 1·2 의존

신규: AIToolRunner.swift  |  수정: TranscribeJob.swift  |  제거: ClaudeRunner.swift · ClaudeBinaryLocator.swift

  • AIToolRunner.generateMinutes — tool 받아 promptVia로 stdin/argTail 분기, 타임아웃·stderr 캡처·AIToolRunnerError
  • TranscribeJob — ClaudeRunner → AIToolRunner(registry.defaultTool()), 미탐지 시 조기 실패 메시지
  • 구 파일 제거 — ClaudeRunner.swift · ClaudeBinaryLocator.swift 삭제, 잔여 참조 정리
GATE: 빌드 통과 + claude 기본값으로 실제 회의록 생성 회귀 테스트(수동)

Phase 4 · 설정 UI — 연결 패널

Phase 2·3 의존

신규: ConnectionsModel.swift  |  수정: SettingsView.swift

  • SettingsCategory.connections 추가(라벨·아이콘) + 패널 라우팅
  • ConnectionsModel — 비동기 프로브로 도구별 AIToolStatus 게시, "테스트"/"자동 탐지" 액션
  • connectionsPanel — 기본 엔진 라디오 + 도구별 상태 카드(연결됨/미설치 · 로그인/확인불가 · 경로 · 버전)
  • 경로 지정… — NSOpenPanel 실행파일 선택·검증·저장
GATE: 빌드 통과 + 세 카드 표시·경로 오버라이드 영속·기본 엔진 전환 영속(수동)

Phase 5 · 문서 · 마감

VERIFY

에러 처리 · 검증

에러 처리

  • 모든 Process 호출: 타임아웃(600s 유지) · stderr 캡처 · 비정상 종료 시 AIToolRunnerError
  • 연결 프로브: 절대 UI로 throw하지 않고 상태값으로 매핑
  • Browse 패널: 선택 파일이 실행 가능해야 저장

검증 (XCTest 타깃 없음 → 빌드 + 수동 테스트 플랜)

  1. claude 회귀: 기본 엔진 claude로 회의록 생성이 기존과 동일
  2. codex/gemini: 탐지/미탐지 상태 정확, "경로 지정…" 오버라이드 영속, "테스트" 재프로브
  3. 기본 엔진 전환 후 실제 생성에 반영
  4. 잘못된 경로 → 명확한 에러 표면화
  5. 구 claudeBinaryPath → aiToolPath.claude 마이그레이션

AITool.invocationArguments(prompt:)와 JSON 디코드는 순수 함수로 두어 추후 단위 테스트 용이.
