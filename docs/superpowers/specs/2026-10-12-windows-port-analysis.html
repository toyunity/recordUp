recordup을 Windows에서 쓰려면

현재 앱은 SwiftUI·AppKit·WhisperKit/SpeakerKit(CoreML)에 묶여 있어 그대로는 Windows에서 돌지 않는다. 다만 모델 원본은 공개 모델이라 플랫폼 독립적이고, Mac 전용인 것은 실행 엔진과 파일 형식이다. 핵심 위험은 STT·화자 분리 엔진 교체에 따른 한국어 품질·화자 수 편차이므로, 골든 테스트셋 검증을 먼저 통과시킨 뒤 Windows 앱을 별도로 만든다.

요약

결론

모델 가중치(Whisper large-v3-turbo, pyannote segmentation-3.0, WeSpeaker, VBx PLDA)는 Windows에서도 쓸 수 있다. 바꿔야 하는 것은 실행 엔진(WhisperKit/SpeakerKit → whisper.cpp + VBx 포함 pyannote community-1 계열), UI 전체, 오디오·내보내기·설치 파일이다.

주의

Mac(4-bit OD-MBP)과 Windows(Q8_0)는 같은 모델의 다른 압축본이라 출력이 글자 하나까지 같지는 않다. 632MB 변형만 따로 잰 공개 WER 수치는 확인하지 못했으니 직접 측정한다.

접근 방식과 트레이드오프

방식장점단점
A. 양쪽 모두 크로스플랫폼 재작성코드베이스 하나맥까지 재작성, 맥 품질·속도 퇴행 위험
B. 맥 유지 + Windows 별도 (권장 시작점)맥 품질 유지, 위험이 Windows에만 있음이중 유지보수, 기능 차이 발생
C. Swift 공통 코어 + 플랫폼별 UI로직 재사용Windows Swift 도구 체인 미성숙, STT는 어차피 별도
D. Windows는 클라우드 STT하드웨어 편차 없음오프라인·로컬 처리 가치 훼손, 비용·개인정보

헷지 수단

  • 골든 테스트셋 관문 — 실제 회의 녹음 + 정답 전사·화자 라벨로 CER·DER·화자 수를 현재 Mac 결과와 비교. 기준 미달이면 중단.
  • 맥 동결 — Windows가 따라올 때까지 맥 앱은 건드리지 않는다.
  • 데이터로 공유 — Resources/prompts/*.md, ai-tools.json, 릴리스 노트, 전사·회의록 .md 형식을 두 앱의 계약으로 삼는다.
  • 하드웨어 단계 — GPU 유무·메모리로 turbo / small·medium 자동 선택, 예상 처리 시간 표시.
  • CLI 인코딩 테스트 — 한글 프롬프트 왕복을 Windows CI에 고정.
  • 서명 예산 — OV/EV 인증서 또는 Microsoft Trusted Signing(자격 확인).
  • 합칠 길 — whisper.cpp는 Metal·CoreML 백엔드가 있어, 나중에 맥도 같은 엔진으로 옮길지 테스트셋으로 판단.

단계별 실행 계획

P1 엔진 검증

1~2주
  • 한국어 골든 테스트셋 구성 (회의 녹음 5~10건, 정답 전사·화자 라벨)
  • 현재 Mac(WhisperKit/SpeakerKit) 결과를 기준선으로 저장
  • whisper.cpp Q8_0/F16 — CPU 전용 노트북, NVIDIA 데스크톱에서 CER·처리 시간 측정
  • speakrs · sherpa-onnx · pyannote.audio community-1의 DER·화자 수 비교
관문 CER·DER이 기준선과 비슷하고, 1시간 녹음 처리 시간이 허용 범위면 P2 진행

P2 Windows MVP

Tauri + whisper.cpp + 화자 분리
  • 파일 선택 → 전사 → 화자 분리 → 화자 매핑 → claude -p 회의록
  • 프롬프트·ai-tools.json 공유, Windows 경로·UTF-8 처리
  • 출력 .md 형식을 맥과 동일하게 유지

P3 배포

설치 파일·서명
  • 설치 마법사에서 AI 도구 선택 (맥 .pkg와 동일 UX)
  • 하드웨어 단계별 모델 선택
  • 코드 서명으로 SmartScreen 경고 완화

P4 통합 판단

선택
  • 테스트셋으로 맥을 같은 엔진으로 옮길지 결정
한계

프록시로 Argmax 블로그·Hugging Face 모델 카드 원문을 직접 열지 못해 일부는 검색 요약에 기댔다. speakrs 성능 수치와 community-1의 정확한 임베딩 모델명은 원문으로 재확인 필요.
